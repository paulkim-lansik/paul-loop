## 1. TL;DR

paul-loop's harness is genuinely solid wherever it's actually been exercised — the ADR archive, loop-engine's core scripts, all 12 ship-flow skills, and the domain-doc-citation discipline all check out against live code with essentially zero drift — but the harness has no evidence of ever having *operated repeatedly* on its own repo: `.loop/` has never existed here, two of loop-engine's own anti-cheating guards are opt-in-off by default, and loop-memory's hooks have never been observed firing in a live session.

## 3. Priority improvement list

**Blocker**

1. **No operational history of the harness running against paul-loop itself** (`.loop` operational data, L0). *Why:* the harness's entire value proposition is a verify→lessons→promote loop that compounds over repeated real use. With zero `.loop/lessons` ever committed or observed, and only one ad hoc "dogfooded" run documented in the README, there is no evidence the harness has ever operated the way it's designed for consuming repos to operate — the "self-improving" claim is completely unproven on paul-loop's own turf.

**Major**

2. **Both of loop-engine's own anti-cheating guards are opt-in and default OFF** (`--guard-mutation` on verdict-run.sh, `--protect` on loop-fix.sh). *Why:* directly reproduced — the exact failure modes these guards exist to catch (a verify script that mutates state to fake a pass; a fixer that rewrites the verifier itself) produce a silent, undetected PASS whenever a caller omits the flag. Nothing forces the flag on, so any consumer wiring — including this repo's own — can ship with zero protection against the harness's headline threat model.
3. **`loop-fix.sh --protect` detects reward hacking but doesn't revert the sabotage.** *Why:* directly reproduced — after a PROTECTED-VIOLATION abort, rerunning `loop-fix.sh` against the same unreverted workspace reports a false SUCCESS because the sabotaged file is still on disk. Any orchestrator that forgets to `git checkout` before retrying will silently launder the cheat as a real pass on the next run.
4. **No evidence loop-memory's hooks have ever fired inside a live Claude Code session.** *Why:* the only data present in the live DB (294 rows, all soft-deleted) matches literal fixtures from the integration test suite, not a real graduated lesson from actual dev-loop use. The feature is built, tested, and wired end-to-end, but nothing shows it has ever actually helped a real session recall a real lesson.

**Minor**

5. **~15 dangling ADR references** (ADR-0061, -0085, -0033, -0054, etc.) inherited verbatim from the origin monorepo litter loop-engine/loop-memory code, almost all unqualified with a repo name. *Why:* an engineer auditing paul-loop in isolation will hit unresolvable citations — only ADR-0001's own text explicitly disambiguates.
6. **5 of ~19 `bin/` tools have zero self-test coverage** (`eval-gate.mjs`, `check-rules-always-on.mjs`, `deps-audit.mjs`, `mattpocock-skills-sync-check.mjs`, and `require-tests.sh` itself). *Why:* these were only verified correct in this audit via hand-written ad hoc fixtures; a future regression in any of them — including in the tool purpose-built to catch fake-green — would go undetected by CI.
7. **`.loop/` is gitignored with no committed low-fidelity trace of local runs.** *Why:* this makes "never run" and "run locally but never persisted" indistinguishable to any outside auditor, undercutting the project's own reproducibility principle.
8. **loop-memory's docker-gated integration suite (32 tests) never runs in CI**, only locally/manually. *Why:* the DB-touching code path (advisory locks, mirror-sync, embeddings) has no regression protection beyond whoever happens to run it by hand — evidence shows this has happened at most once before this audit.
9. **The plain-GitHub-Issues tracker convention, and the silent switch away from inherited Linear-style `BAC-*` labels, are nowhere documented.** *Why:* a newcomer or fresh agent session must reverse-engineer both from `git`/`gh` history instead of being told.
10. **Hardcoded `@glucofit-partners/loop-memory` string** in `lessons.mjs`'s runtime stderr hint. *Why:* names the wrong package in any other consuming repo, undercutting the "portable, consumer-agnostic plugin" framing.
11. **Workflow-invocation-name mismatch**: `harness-maturity-audit/SKILL.md` calls `Workflow({ name: 'ship-flow:harness-audit' })` while the workflow file's own `meta.name` and header comment say `'harness-audit'`. *Why:* two source-of-truth comments in the same repo disagree on the literal invocation string; unresolved because no `Workflow` tool was available to test directly during the audit.
12. **ADR-0104 and "ADR-0062 decision 9," cited as canonical justification in merged code/tests, live only in glucofit-partners.** *Why:* a fresh clone of paul-loop cannot read the full reasoning behind design choices its own shipped code depends on.
13. **No `CONTEXT.md`/glossary-equivalent for paul-loop's own terms, and the repo doesn't dogfood its own recall hook against its own `docs/adr`.** *Why:* the automated retrieval path shipped for consumers is untested on the one repo best positioned to validate it end-to-end.
14. **The "grounded reopen" ADR-supersession policy has zero exercises in this repo's own archive.** *Why:* designed but unproven — no evidence an agent actually cites-id-plus-new-evidence when attempting to reopen a settled ADR.
15. **No machine-checked ADR hygiene gate** (numbering uniqueness, dangling-reference check, README index completeness). *Why:* unlike the origin monorepo, which built exactly this kind of verifier for itself, paul-loop's ADR convention here relies only on skill-prose discipline, not an enforced check.

## 4. Strengths worth keeping

- **"Verifier = ceiling" is structurally enforced, not just asserted**: `verdict-run.sh` labels parsed test counts "advisory only; never affects VERDICT" in its own source — PASS/FAIL comes only from the wrapped command's exit code.
- **`require-tests.sh`** correctly refuses to certify PASS when zero tests match — the harness's purpose-built defense against the canonical fake-green case, verified directly.
- **`classify-risk.mjs`'s "escalate only, never soften" invariant** (`final = max(rule, agent)` per dimension) holds under direct adversarial input, not just in comments.
- **`loop-fix.sh`'s closed verify→fix→re-verify loop actually converges** on realistic synthetic fixtures, with a dual-signal stall detector that correctly distinguishes real progress from a frozen retry.
- **The reward-hacking guard (`--protect`) correctly detects and reports sha256-level tampering** of a protected verifier file, with visible before/after hash evidence.
- **A 16-file self-test suite** covers fail-closed paths, corrupt-ledger resilience, `__proto__`-poisoning resistance, byte-identical determinism, and nested-wrapper double-count prevention — and is genuinely wired into CI (confirmed by running the same `claude plugin validate --strict` command CI runs).
- **Documentation is unusually honest about its own limits in-line** (e.g. `--guard-mutation`'s opt-in nature, loop-fix's "Guard scope — the guarantee is narrow") rather than overclaiming.
- **All 3 ADRs on `origin/main` cross-check against live code with zero drift**, each tracing through a real closed GitHub issue back to a real Linear issue in the origin monorepo.
- **New ADRs are demonstrably written only after reading prior (even cross-repo) decisions** — PR #26's body documents reading glucofit-partners' ADR-0021/0023 before drafting paul-loop's ADR-0001.
- **Docs get amended mid-review in response to real findings**, not written once and abandoned (ADR-0002 updated after an adversarial-review round found a new limitation).
- **All 12 ship-flow skills' bundled files, CLI flags, and named agents resolve to real artifacts** — zero broken cross-references found, and mechanism-level claims (e.g. `tdd`'s guard-off TTL) match implementation line-for-line.
- **loop-memory's hooks are strictly fail-open and self-gating** (always exit 0, no-op without an embedder key), verified by dedicated CI smoke tests, so the feature cannot break a session even when misconfigured.
- **loop-memory's concurrency design is backed by a real documented incident**: session-scoped advisory locks were deliberately chosen after a PR review caught that transaction-wrapping the sync would roll back on the SessionStart hook's timeout.
- **Cross-repo provenance discipline**: multiple issues/PRs explicitly note "ported from glucofit-partners Linear BAC-XXX" rather than silently dropping lineage.
- **The issue-tracker claim is fully corroborated**: 11 real, closed GitHub issues match PR titles and branch names 1:1 across the last 30 `origin/main` commits.
