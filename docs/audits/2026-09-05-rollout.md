# Main and installed-plugin rollout

The repository owner explicitly requested main integration, marketplace refresh and an inventory/update of existing installations after receiving the compatibility review. PR #93 records this approval and the 14 intentional baseline-script conflicts without converting the pinned FAIL into PASS.

## Hosted validation discovered during rollout

The first PR run at `b9b2087` passed memory, security, all Linux/macOS × Node22/24 packaging combinations and both Claude schema versions. The full Linux engine suite reported 79/80: sanitizer fixture T15 removed Node altogether to simulate sanitizer failure. Node is now also required for pre-dispatch verification-target capture, so the command correctly refused setup with exit 2 before the test reached its intended behavior. macOS had skipped that conditional fixture when a system Node was present.

T15 now always runs on every host with a shim that fails only the sanitizer, observes actual verifier dispatch, and retains the raw-log, warning and command-exit assertions. A separate T15b asserts that an unavailable required Node runtime refuses setup before command dispatch. Runtime behavior and failure coverage have not been weakened.

The first Linux pinned run reported 64/80, including two additional lifecycle/protected-file failures beyond the documented 14 conflicts. These extra failures are not presumed approved compatibility changes; follow-up results are required before rollout completion.
